# Project memory

Fan-made Star Trek RTS design package plus a playable Godot prototype. `README.md` lists every page, data file and artifact link; `GDD.md` is the design document. Keep both in step with the data.

## Design rules decided so far

- Seven great powers (see `tools/faction_meta.py` FACTIONS); 28 factions in `data/factions.json`.
- **Borg never research.** `tech_tree.json` → `faction_rules.borg`: `research: false`; they assimilate techs and combine them, costing 20 nanoprobes × tier. `tools/tech_access.py` `reachable()` honours this.
- Terraforming runs K → L → M.
- Dominion War era is 2373–2379; `eras.json` and `factions.json` must agree.
- Galaxy map (`data/galaxy_map.json`): Sol-centred light-years, +x toward Beta, +y toward the core (core at 0, 26000). Routes use the stable Bajoran wormhole but skip the unstable Barzan wormhole (opt-in checkbox in the planner); transwarp is Borg only. Match drive speeds are placeholders: Warp 5 = 30, Warp 8 = 60, Warp 9.9 = 110, slipstream = 300 ly per minute of play.
- All numbers are placeholders for balancing.

### Data files (split 2026-11-06; owner: "split up information so that mass changes won't kill our game", "combine them into ... a binary format so users can't adjust")

- **Layout:** each of the 14 data documents (achievements since 2026-11-08, the only optional one) is a folder `data/<doc>/` of small files, roughly one per table or record family, one per record for the big ones (`buildings/surface/<building or family>.json`, `surfaces/units/<id>.json`, `climate/climates/<template>.json`, `buildings/faction_lines/<faction>.json`, …). `data/manifest.json` lists each document's files in order; the loaders merge them top-down (the same table in several files is joined: lists one after the other, objects key by key, recursively; the same plain key twice is a problem). Each part keeps the wrapper of where it lives (`{ "buildings": [ … ] }`), so a file says where it goes. A doc's big `_notes` is in its `notes.json`; `_notes_*` tables went with their table. A .json under data/ that the manifest doesn't list is reported by `Validate()`. In these notes "surfaces.json", "buildings.json" etc. mean the document (its folder). The split was done by `tools/split_data.py` (one-time; cuts the original text so the layout stays; if main changed a flat data file before this merged, restore the flat files and re-run it), checked by the golden test `SplitGoldenTests` (pre-split document hashes + a scripted game's state hash in `game/tests/…/Golden/presplit.json`; it stops applying once the data is edited) and by the page HTML coming out unchanged.
- **Loading:** `GameData.Load(dataDir)` = base data, no layers, no draft: the entry point for tools (tests, `tools/BalanceRunner`); `GameData.Load(dataDir, new DataSetup(Era, Factions, Scenario))` adds layers; `GameData.Load(files[, setup])` from texts by path; `GameData.LoadPack(bytes[, setup])` from the release pack. `GameData.Documents` = the 9 the sim reads; `Sources` = every file it was loaded from by path ("manifest.json", "surfaces/orbit.json", "layers/eras/ent.json"; pre-layer, draft already in); `Files` = the sim documents' files in order (the DATA tab's list); `Setup`; `Fingerprint`. `GameData.FileNames` is gone (use `Documents` / `Files`). `GameData.FindDataDirectory` looks for `data/manifest.json`. Code: `sim/Data/DataManifest.cs` (+ `DataFingerprint`), `DataDocument.cs` (the Data Lab's "phase 0": every value's text span, id paths, edits that keep the layout), `DataLayers.cs` (`DataSetup`, `DataPatch`, `DataLayer`, `DataPatcher`), `DataStore.cs`, `DataPack.cs`, `DataChecks.cs`. Python: `tools/data_loader.py` `load("buildings")` (same merge; base only), used by every `gen_*` script.
- **Layers** (`data/layers/eras/<era>.json`, `factions/<faction>.json`, `scenarios/<id>.json`): `{ "_notes", "patches": [ { "op", "doc", "path", "value", "after" } ] }`; ops `set` (existing value), `remove` (field or record), `add_field`, `add_record` (id/class/name must be new; optional `after`), `list_add` / `list_remove` (plain lists such as build_menu); paths by id: `units/mining_crawler/breakdown/chance_per_min` (a record in a list by its id, else class, else name; plain items by position). Applied to copies of the files' text in the order era → each faction → scenario; a missing era/faction layer = no overrides, a missing scenario is a problem. An era layer sets `orbit/era` itself. `Validate()` checks every layer alone against the base (each patch must fit) and reports conflicts (two layers that can meet in one game touching the same path; the later wins). Examples: `eras/ent.json` (orbit era ent → early transporter, NX-01 for earth_uec, a Raptor for the Klingons), `scenarios/quick_start.json` (bigger start stock, 5 s assembly, a construction rover). Nothing was migrated: the transporter `by_era`/`factions` tables stay in surfaces.json because they're resolved per player in one match (a faction layer applies to the whole match's data, so faction layers should only touch that faction's own entries). The game passes `new DataSetup(Factions: …)` (no layer files for them yet, so the base is unchanged).
- **Draft → Promote:** the Test panel DATA tab's Save writes `data/_draft/draft.json` (a layer of `set` patches by id path, recomputed against the base on each save; other patches in it are kept), never the base files. Debug runs load base + draft (`DataStore.LoadForGame`). **Promote** (DATA tab button, `dotnet run --project tools/DataPacker -- promote`, or `DataStore.Promote(dir, stamp)`) applies the draft to the base texts, runs `DataChecks.All` (Validate incl. layers, `PlanetProblems` for seeds 1/1701/99999 (the PlanetsArePlayable rules), `SymmetryProblems` (point-symmetric duel map + twin climates)); only if all pass does it write the changed files (token edits, layout kept), with the replaced files + the draft in `data/_backups/<yyyyMMdd-HHmmss>/`, and remove the draft. The Python page checks are not run (regenerate the pages after promoting). Discard draft backs it up first. `data/_draft/`, `data/_backups/` and `game/gamedata.pack` are git-ignored.
- **Mass changes:** `DataStore.LoadForGame` refuses data that fails `Validate()` (or doesn't load): base + draft → base → `data/_backups/last_good.pack` (written whenever a load passes) → failing data with its problems; `Refused` explains each step (Output panel errors + red event-feed lines in the game).
- **Release pack:** `dotnet run --project tools/DataPacker -- --out game/gamedata.pack` (also `check [--draft]`, `fingerprint [--pack f]`; `tools/DataPacker` is in FinalFrontier.sln) checks the base data with `DataChecks.All`, then writes `DataPack`: magic `FFDATA\r\n`, format 1, the SHA-256 data fingerprint, SHA-256 of the body, body length, Brotli-compressed body (file count, then path + text per file); ~43 KB for 125 files. `DataPack.Read` refuses a bad magic/version, wrong length, body hash or fingerprint. Fingerprint (`DataFingerprint.Of`) = SHA-256 over every file's path + compact JSON, sorted by path: layout and CRLF don't count, values do; the folders and their pack give the same one. Godot: `scripts/GameDataLoader.cs` — `OS.IsDebugBuild()` and a data folder found above `res://` → JSON + draft; otherwise (release exports, or a debug export without the folder) only `res://gamedata.pack` via `Godot.FileAccess.GetFileAsBytes` (works inside the .pck). The JSON folders are outside `game/`, so never exported; the owner must add `gamedata.pack` to the export preset's "Filters to export non-resource files/folders" (no `export_presets.cfg` exists yet). Test panel / Data Lab are debug-only (`OS.IsDebugBuild()`); its file buttons say so when the data came from the pack.
- **Not security:** the pack only deters casual edits (anyone with the code can rebuild one). The real check for multiplayer is the state hash; the future lobby should compare `GameData.Fingerprint` (+ the `DataSetup`) of every player before starting (`sim.Data.Fingerprint`; it is not in `StateHash()`, which already diverges when the data's effects differ). Stronger: Godot PCK encryption (build custom export templates with `SCRIPT_AES256_ENCRYPTION_KEY` set, put the key in the export preset's Encryption tab, encrypt the .pck and `gamedata.pack` in it) — documented only, not done; the key ships inside the binary, so it's still only a deterrent.

### How it works now

- **Surface** (`game/sim/Surface/`, `data/surfaces.json`): seeded, deterministic generation; elevation and moisture are *ranked*, so thresholds are shares of the map. Test `PlanetsArePlayable` checks a few seeds have landing sites and basic deposits. Landing rules, rover stats, `build_menu`, `hud_resources` and `power_resource` live in surfaces.json. Map size is just `width`/`height` there: the camera overview, zoom limit, haze and shadow distance are derived from it in `PlanetDriver`.
- **Buildings** (`buildings.json` `buildings`, all optional placeholder numbers; Colony Hub power 36 (was 30) and Research Lab 16 points/min (was 10) since the 2026-11-07 retune): `build_seconds`, `output_per_min`, `upkeep_per_min`, `power_supply` / `power_use`, `requires_deposit` + `extract_per_min` (mines; they currently turn deposits straight into finished metal), `build_radius` + `build_queues` (colony cores), `level` + `upgrades_to` (Colony Hub 1 → Colonial Administration 2 → Planetary Capital 3; validated from the landing hub up). Planetary Capital costs Parasteel and Isolinear Chips, which nothing produces yet.
- **Bases:** a core plus the buildings in its radius (`BaseId` = nearest core in range when placed). Each base has its own build queues and power budget; over-use slows every power user there to supply ÷ use. Energy must not appear in a surface building's output/upkeep or the landing stock (validated). Other buildings in buildings.json still list energy as a *cost*; fix those when they join the build menu.
- **Storage:** `PlanetSurface.StorageCapacity` = sum of `storage` on finished buildings; `Stored` counts every resource except `storage_exempt` (crew, latinum) and power; `FreeStorage` also subtracts cargo pods in flight. Building output and mines go through `Store` (only what fits); converters spend input first and add output directly; refunds/salvage ignore the cap. Capacities since the economy retune (2026-11-07): hub vault 1500 (owner), Storage Container 1000 (was 2000), refinery 200 (was 300), Colonial Administration 2500.
- **Ore and converters:** `duranium_ore` in hills + plains (chance 0.15, 1200–3000; plains are landing ground, so the hub's radius usually has some), `tritanium_ore` in hills only (0.12, 800–2400; often a crawler drive away) — retune 2026-11-07, was duranium hills-only and tritanium hills+plains, which put tritanium (needed ~1/3 as much) in the hub's radius. Mine 80 ore/min (was 40), deep-core 48 (24), crawler 60 (30, hopper 20), refinery 25 cycles = 50 ore/min (20): one crawler keeps a refinery busy, a mine on top piles ore up (storage fills fast, a second refinery or Mk II is the answer). `recipes` + `cycles_per_min` (refinery 2 ore → 1 metal, foundry 2 dur + 1 tri → parasteel) share cycles between recipes that have input; no input → `NoInput`. Idle statuses (NoUpkeep, Depleted, StorageFull, NoInput, Paused) draw no power.

## How the pages are built

- Each page: `tools/gen_<x>_page.py` reads the data documents through `tools/data_loader.py` (`load("buildings")` joins `data/buildings/…` per `data/manifest.json`) + `tools/faction_meta.py`, replaces `/*DATA*/` in `tools/<x>_page.html`, writes `<x>.html` at the repo root.
- Shared dark "console frame" style; every page ends with a data-checks list, which should come back empty. When a page flags gaps, fix the data rather than the check.
- After any data change: rerun the affected `gen_*_page.py`, then `python3 tools/build_site.py` (builds `docs/` for GitHub Pages; new pages go in its PAGES list and in README).
- Data JSON is hand-formatted: edit the small part files with targeted unique string replacements, not full rewrites. One-object-per-line files (tech_tree, ships, vehicles, hazards) keep that layout. New file → add it to `data/manifest.json` (unlisted files are reported). `tools/gen_data_lab_mockup.py` is a snapshot of the flat pre-split files: run it on an older checkout.
- Test pages with Playwright at 1400 px and 400 px: no horizontal overflow, no console errors.
- Each root page is also published as a claude.ai Artifact (links in README); republish after regenerating. Artifacts are private until shared from the page's Share menu.
