Build Menu Cards

The owner asked for building pictures on the HUD and a card that explains everything about a building when you click its build icon. This page shows three ways to put renders on the command card, two building-card layouts with every number from the data files, and how to make the pictures in Godot.

Data: buildings.json + surfaces.json, 2026-11-06 Real model rendered from the game glb Stand-in rebuilt from the primitives in BuildingModels.cs

Part 2 · Building card

Click a building, read everything

The card works like the tech and vehicle cards already do (CLAUDE.md "Info cards"): the first pick opens it, the card's button, Enter or a second pick acts. For a building, acting means placing. Today a building pick arms placement straight away; this changes it so the card comes first.

Hover a tileTooltip: name, cost, build time, power, one line of what it does.
Click it, or press 2The card opens with the picture and every number. The base's build area shows on the map; clicks on the map do nothing yet.
PLACE, Enter, or pick it againPlacement is armed: the card shrinks to the placing strip with the ghost under the cursor. Shift+pick skips the card.
Click a tilePlaced. Shift+click keeps placing, R turns 60°, Esc steps back one stage.
1

Compact side card

WhereAbove the command card at the right edge, 470 px wide, the same place and width as PlanetHud.ShowInfo.

FitsAbout 600 px free between the top bar and the bottom panel in the game's 1600 × 900 window; the card is about 550 px tall, with the details in tabs that scroll.

Good forQuick decisions with the map in view; the placing strip is the same card, shrunk.

2

Large centre card

WhereCentred over the map (world dimmed, game keeps running), up to 1120 px wide; two columns.

FitsEverything at once: production, levels, research that changes it, placement, links, wear and tips. In the game window the right column scrolls past about 780 px.

Good forLearning the economy, and later the faction buildings. Enter places and drops back to the compact strip.

Recommendation

Use both, each for one stage. The first click opens the large card (the owner asked for a card that explains everything); Enter places and the compact card stays as the placing strip, so the map is clear while you pick a tile. Players who know the building use Shift+pick to go straight to placing.

Part 3 · In the game

How it would work in Godot

Two ways to get the pictures into PlanetHud.

Rendered at runtime

A SubViewport with its own World3D, a fixed 3/4 camera, three lights and a transparent background. At start-up it builds each build-menu model with BuildingModels.Build(id, owner) (the plain look, no variety add-ons), renders one frame per building, and keeps GetTexture().GetImage() as an ImageTexture for the tile.

  • Always matches the game: new glbs (mine, storage, reactor) and primitive changes show up with no extra step.
  • Player colour, and later Mk II / III models, come for free.
  • The card's turntable can be the live model turning in the same viewport.
  • Costs about a frame per building at start-up (9 × 256²); Godot's lighting is plainer than these Cycles renders.

Pre-rendered images in the repo

Render with blender/render_build_cards.py (the script that made this page's images), commit JPEGs or WebPs under game/textures/ui/buildings/, load them like the planet photos.

  • Nicest pictures (Cycles, soft shadows, AgX).
  • Goes stale every time a model changes, and someone has to remember to re-run the script.
  • One colour only unless rendered per player; about 2–4 MB more in the repo.
  • No live turntable; the card cycles four angles instead.
Recommendation

Render at runtime. The models change every week right now, and the game already builds every one of them. A small BuildingThumbnails class would own the viewport, render the thumbnails once after loading (cached by id and owner colour) and lend the viewport to the large card for the turntable. Keep the Blender script for pages like this one.

// sketch, not game code
var vp = new SubViewport { Size = new Vector2I(256, 256), TransparentBg = true, OwnWorld3D = true,
                           RenderTargetUpdateMode = SubViewport.UpdateMode.Once };
vp.AddChild(studioCamera); vp.AddChild(keyLight); vp.AddChild(rimLight);
var model = BuildingModels.Build(defId, PlanetDriver.PlayerColors[0]);
vp.AddChild(model);                       // fit the camera to the model's AABB, 38° round, 27° down
await ToSignal(RenderingServer.Singleton, RenderingServer.SignalName.FramePostDraw);
Thumbs[defId] = ImageTexture.CreateFromImage(vp.GetTexture().GetImage());
model.QueueFree();
Part 4 · The images

What is real, what is a stand-in

All renders: Blender 5.0 Cycles, 32 samples, denoised, AgX, the same 3/4 camera (38° round from the front, 27° down) fitted to each model, a shadow catcher on the HUD's navy. Thumbnails 512², card angles 1024 × 768, four angles 90° apart. Only the refinery has a game glb among the build-menu buildings on this branch; the others are rebuilt from their primitive builders with the same sizes, colours and materials, so they look like the game does today. That includes one thing that looks like a slip in the game's code: the Mining Complex and Deep-Core Mine derrick legs lean outward at the top, where the builder's comment says they meet under the cap.
